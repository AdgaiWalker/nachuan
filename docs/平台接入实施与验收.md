日期：2026-11-01。本文约束后续工作顺序，并记录真实平台验收状态；历史研究资料中的平台能力和协议须重新核实。

## 当前状态

- 通用内核已完成本地假上游验收；用户选择本机 WorkBuddy 网关作为首个接入对象。其他三个现有插件仍是通用适配骨架。
- WorkBuddy 采用本地桥接，平台账号由原服务管理；纳川插件的凭证是原服务的本地 API Key。密钥仅在本机使用，不写入聊天、日志或证据。
- 百炼不再作为默认首选；其官方模型列表与当前通用探活接口不同，如以后选择百炼需单独适配和验收。
- 2026-11-01 在独立临时 Python 内核中连接 `127.0.0.1:7863`：模型目录 HTTP 200 且包含三个声明模型；`workbuddy:glm-5.2` 映射至 `cn:glm-5.2`，普通和流式聊天均返回 HTTP 200 和非空生成内容，流式正常结束。该过程未更改或重启既有 7863/7865 服务。此为桥接聊天实测，不证明所有模型、平台私有协议、额度或完整 DoD 可用。
- WorkBuddy 本轮最终全量 `bash scripts/test.sh`：Python 103 项、TypeScript 29 项、控制台 13 项通过，控制台构建通过。新增回归使用本地假网关，检查账号 API 录入、鉴权、探活、模型映射、聊天、积分映射、断流以及账号动作的幂等和未知状态；不使用真实密钥。控制台账号缓存、账号操作和流式试用入口另外通过假服务的浏览器交互验证。
- 运行中的 7865 进程尚未加载本次插件修改，也未录入 7863 网关密钥；需在合适的运行实例中加载新插件并通过控制台添加本地网关账号后使用。
- 本轮在独立临时内核中，只读验证 WorkBuddy 专属连接检查和 `gateway_accounts` 动作：前者就绪，后者成功读取本机原网关缓存（223 条，未截断）。缓存的积分可能为未知或过期；原网关没有提供可靠更新时间，不能作为实时余额或计费依据。动作结果含账号标识及缓存积分，会保存在纳川本地有界动作历史，需按敏感运维数据保护。
- WorkBuddy 响应明确提供非负有限的 `usage.credit` 时，按 `workbuddy_credit` 单位记录；没有明确数据时保持未知，不估算。升级后在独立临时内核中再次实测普通及流式请求，均有非空内容，且均收到该积分字段；流式有结束标记。原网关内部账号的额度不伪装成纳川桥接账号的额度。
- 流式上游若未发送 `[DONE]` 就结束，纳川将其视为失败；首块后只能以 SSE 错误报告。要求使用该通用适配器的上游遵循此结束标记。
- WorkBuddy 已提供逐个暂停、恢复原网关账号选号的动作，只在手动触发后调用原网关；暂停不停止原网关的保活等任务。动作使用幂等键，不自动重试，超时、取消或上游未确认时记为 `unknown`，应先核对原网关状态再决定后续操作。控制台在本次浏览器会话保存账号标识和操作锁定状态；会话结束后该锁定不再保留。仅使用本地假网关验证，尚未对现有真实账号执行暂停或恢复。
- 控制台增加 WorkBuddy 流式试用页、单插件连接测试、原网关账号缓存及账号暂停/恢复入口；已在独立假服务中做浏览器交互验证。试用请求可能消耗原账号积分；试用页不执行模型返回的工具调用。

## 实施顺序与门槛

1. **确认首个平台**：记录授权方式、官方协议或获授权接口、可用模型、地域及费用约束；核对接口文档和许可。凭证只在本机控制台或受限文件中录入。
2. **打通最小调用**：按实际协议实现插件，并用本地假上游覆盖鉴权、模型映射、非流式、流式、错误和取消。真实环境验证普通与流式调用、客户端识别及使用量；记录上游可能计费，避免自动重复。
3. **完成首个平台 DoD**：逐项验证账号录入、可用额度与上游对齐、模型动态挂载、面板测试、SSE 及日志；对于上游不提供的能力，明确标记不支持，不伪造数值或成功状态。原七项标准见 [接入 DoD](03_技术规范与标准契约/06_2API项目接入成功标准与形态定义_DoD.md)。
4. **第二平台暂缓**：用户目前只做 WorkBuddy；将来接入不同协议或鉴权形态时，复验相同流程，再依据实际差异修订插件契约。
5. **再建设编译辅助**：基于前两个案例生成当前 `spec.json`、插件草稿和测试模板；人工核对授权和协议，门禁实际运行生成插件。旧 Cordis 编译器及其假上游检查不证明当前插件或真实平台可用。

## 每个平台验收记录模板

| 项目 | 需记录的结果 |
|---|---|
| 平台、授权方式、接口和模型 | 名称、协议、地域、文档链接与核验日期；不记录秘密 |
| 凭证与账号 | 录入、校验、启停、轮换及重启后的状态 |
| 调用 | 非流式与 SSE；模型映射、结束标记、取消与错误；注明是否真实上游 |
| 额度与专属能力 | 来源、单位、更新时间，与上游是否一致；不支持或未验证时明确标记 |
| 控制台与外部客户端 | 按 DoD 逐项记录操作和实际结果；保存无秘密的必要证据 |
| 稳定性与限制 | 限流、失效、重启、已知差异、调用费用及未测范围 |

## 不可省略的边界

- 本地进程分离用于故障隔离，不是权限或网络沙箱；仅运行可信插件。
- 凭证遮盖不能保证识别任意编码或变换；插件不得输出秘密。现有文件存储与账本不提供多用户隔离或计费级持久性。
- 模型及参数能力以各插件实际实现和验收为准，不承诺跨平台无损。配置故障转移前必须确认用户同意数据发送至备选上游、模型能力匹配及费用变化；流式首块后出错只能报告错误，不能透明替换已输出内容。当前实现仍需针对具体平台验证错误分类和重试语义。
- 平台没有提供的额度、模型或操作能力显示为未知或不支持；不要推算成真实上游数据。
