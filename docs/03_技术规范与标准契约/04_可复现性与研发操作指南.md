## 1. 硬件与环境依赖基准 (Prerequisites)

本项目严格贯彻**“个人极简专用 · 零 Docker 负担 · 本地自足”**哲学，不依赖容器守护进程，环境要求极低：

| 依赖组件 | 建议版本 | 必要性 | 验证命令 | 用途说明 |
|---|---|---|---|---|
| **Operating System** | macOS 12+ / Linux (Ubuntu 20.04+) / Windows 10+ | 必选 | `uname -a` | 原生运行操作系统 |
| **Go 工具链** | Go 1.22.0 ~ 1.23.x | 必选 | `go version` | 编译宿主网关与 2api 编译器 |
| **GNU Make** | 3.81+ | 必选 (Win 可选) | `make --version` | 执行自动化构建与测试 |
| **cURL / Python3** | Python 3.9+ (无需额外 pip 包) | 可选 | `python3 --version` | 执行自动化积分任务与探针工具 |
| **Docker** | **完全不需要** | **禁止依赖** | - | 彻底剥离，无需安装启动 Docker |

## 2. 从零全量冷启动复现流程 (Cold-Start Flow)

任何全新的本地工作站或 Agent 沙箱，仅需按以下标准四步即可完成 100% 确定性复现：

### Step 1: 检出源码与目录完整性校验
```bash
# 1. 进入工作区
cd /path/to/workbuddy2api-panel

# 2. 检查目录拓扑
ls -la
# 预期可见: cmd/ internal/ scripts/ 2api-agent-compiler/ Makefile README.md config.example.json
```

### Step 2: 编译宿主网关与全套运维工具 (`nachuan`)
```bash
make build
```
* **构建产物断言**：
  - `bin/nachuan`：主服务与 Web 控制台单二进制（约 12MB）；
  - `bin/login`：OAuth 设备流授权工具；
  - `bin/signin`：批量签到运维工具；
  - `bin/credit`：积分查询与日报汇总工具；
  - `bin/trial`：global trial 体验包领取工具。
* **执行单元测试检验**：
  ```bash
  make test
  ```
  *预期输出*：20 个内部包测试全部 `ok`，0 failed，0 warning。

---

### Step 3: 编译与验证 `2API Agent 编译器`
```bash
cd 2api-agent-compiler

# 编译独立编译器 CLI
make build

# 运行编译器内部假上游打桩沙箱测试
make test

# 运行端到端模拟逆向转译样例
make run-example

# 返回主目录
cd ..
```
* **断言标准**：
  - `2api-agent-compiler/bin/2api-compiler` 顺利生成；
  - 假上游打桩门禁耗时 `<50ms`，且 `VerificationReport.Passed == true`。

---

### Step 4: 启动主服务并验证 Web 控制台
```bash
# 首次启动：准备本地配置文件（若无则从样例复制）
if [ ! -f "config.json" ]; then
    cp config.example.json config.json
fi

# 原生启动服务
./bin/nachuan
```

* **预期控制台输出日志**：
  ```
  2026/10/30 20:20:00 nachuan listening on :7863 (api_key=true)，管理面板 http://127.0.0.1:7863/panel/
  ```
* **健康检查冒烟断言**：
  新开一个终端窗口执行：
  ```bash
  curl -s http://127.0.0.1:7863/healthz
  # 预期返回: ok
  ```
* **打开浏览器访问 Web 控制台**：
  访问 `http://127.0.0.1:7863/panel/`，网页标题与侧边栏应为 `nachuan (纳川)`。

---

### Step 5: 验证动态 2API 微内核插件与插件中心
```bash
# 1. 验证聚合模型清单（包含 workbuddy, hellogml, qwen 共 12 个模型）
curl -s http://127.0.0.1:7863/v1/models -H "Authorization: Bearer $(grep api_key config.json | cut -d'"' -f4)" | grep -o '"id":"[^"]*"' | head -n 12

# 2. 验证控制台插件接口与热重载
curl -s http://127.0.0.1:7863/panel/api/plugins -H "Authorization: Bearer $(grep api_key config.json | cut -d'"' -f4)"

# 3. 访问 Web 插件中心可视化卡片
# 浏览器打开: http://127.0.0.1:7863/panel/#plugins
```
* **断言标准**：
  - `plugins/` 目录下的所有 `spec.json` 插件全部自动挂载（`total >= 3`）；
  - 页面「插件中心」能够清晰展示上游端点、认证模式、超时与暴露模型映射表；
  - 点击「重新扫描 / 热重载」返回 `ok: true` 且无需重启网关进程。

## 3. 常见复现故障与确定性排错 (Troubleshooting Matrix)

| 异常现象 | 诱因剖析 | 确定性解法 |
|---|---|---|
| `bind: address already in use :7863` | 本机已有其他残留进程占用了 `7863` 端口 | 执行 `lsof -i :7863` 查出 PID 并 `kill <pid>`，或在 `config.json` 中修改 `"listen": ":7864"`。 |
| `no auth for ...` (运行 scripts 脚本时) | 历史脚本硬编码了容器目录 `/root/...` | 确认已使用本次重构后的脚本，它会自动嗅探当前项目根目录下的 `./auths`；或显式指定 `export AUTHS_DIR=./auths`。 |
| `open config.json: permission denied` | 文件属主非当前登录用户（历史 Docker 残留权限错配） | 执行 `chown -R $(id -un):$(id -gn) .` 夺回本地文件所有权，再无 Docker UID 映射问题。 |
| 浏览器提示登录授权失败 / 无法回调 | 本机网络代理或 DNS 解析异常 | 确保能正常访问 `https://copilot.tencent.com` 或 `https://www.workbuddy.ai`，或在 `config.json` 中配置 `"proxy"`。 |

## 4. 离线备份与迁移复现协议 (Backup & Portability Protocol)

由于系统完全遵循“本地文件自足”架构，**无任何隐式外部数据库或容器卷**，系统整体备份迁移只需保存以下 3 个要素：

```bash
# 一键归档个人自足数据包 (仅需 2 秒)
tar -czvf nachuan-personal-backup-$(date +%Y%m%d).tar.gz \
    config.json \
    auths/ \
    data/

# 在任意新机器上解压即完整恢复：
tar -xzvf nachuan-personal-backup-*.tar.gz
make run
```
