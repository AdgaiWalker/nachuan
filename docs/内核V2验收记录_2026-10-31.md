## 公开 API

除 /health 外，沿用现有 Bearer 鉴权。

- GET /kernel/plugins/{name}/descriptor：公开 schema、模型能力及运行时实际支持能力。
- GET /kernel/models：完整能力目录；/v1/models 继续提供兼容客户端目录。
- GET/POST /kernel/plugins/{name}/accounts：读取公开状态/添加任意 schema 凭证。
- PATCH /kernel/plugins/{name}/accounts/{uid}：持久化 enabled/maxInFlight。
- POST .../accounts/{uid}/rotate：credential 完整替换 + expectedGeneration；冲突 409。
- GET /kernel/plugins/{name}/actions：动作声明和 supported 状态。
- POST .../actions/{id}/runs：input/accountId/idempotencyKey，返回 202 及运行 ID。
- GET /kernel/action-runs/{id}；POST .../{id}/cancel：状态、公开结果、取消。
- GET .../accounts/{uid}/quota；POST .../{uid}/quota/refresh：缓存快照和受控刷新。
- /kernel/tasks 继续提供周期任务与历史；任务支持独立 id、accountId、input。

新版请求例子（值仅为占位符）：

```json
{"id":"account-1","credential":{"cookie":"REPLACE_LOCALLY","csrf":"REPLACE_LOCALLY","workspace":"workspace-1"},"enabled":true,"maxInFlight":1}
```

旧 `{id,apiKey}` 添加和 `{apiKey}` 轮换仍经兼容适配器处理。协议 1 未实现的新能力返回 unsupported，不伪造可用状态。原四个平台骨架不自动转换为真实平台实现。

## 运行语义

- 新插件用 `specVersion:2`；动作和模型参数 schema 使用 nachuan-schema/1 支持子集，不支持的关键字会拒绝。
- 任意结构凭证保存为 formatVersion 2 envelope；只给插件发送 secret，公开状态不含原始秘密。
- 显式 credential 轮换是完整替换；旧刷新补丁保留适配合并语义。更新都使用磁盘 generation 防覆盖。
- 同一目录的在用账号对象及锁跨代际共享，旧插件的失败状态不能因新实例发布而失效。
- 维护动作、聊天和额度查询共用宿主并发计数。重新授权状态的账号可执行刷新；停用账号仅允许明确声明的凭证管理动作。
- 没有可靠 reset 信息的额度耗尽不会按固定一小时自动复活；后续成功的非耗尽查询或显式凭证恢复可解除。
- 已发送到上游的副作用动作在取消、超时或崩溃后标记 unknown；相同幂等键不自动重放。不承诺远端 exactly-once。
- 查询过期或失败时不伪造零余额；只有新鲜且声明可据以阻断的配额才阻止聊天选号。
- 不同插件的点数即使同名，也分开结算；不同货币/维度不提供混合 cost 总和。

## 已知边界

1. 验收证明的是本方案定义的**本地通用内核**，不代表四个平台接入完成，也不代表公网生产服务验收。
2. 持久化沿用本地原子文件、单宿主模型；不提供跨 OS 进程锁、fsync 级计费承诺或数据库事务。
3. 动作历史上限 500；可回收只读终态记录。带副作用的幂等记录不静默删除；满容量时返回 503 action_history_full，需受控归档/迁移后继续。当前未提供自动归档接口。
4. 调度为固定间隔，未实现 Cron/时区日历语法。
5. 旧 configSchema 不自动推断为 credentialSchema；旧插件需显式迁移字段与实现新 handler。
6. 未进行浏览器视觉验收；新增宿主能力暂通过 HTTP API 提供，控制台消费另行实现。

## 迁移与回退

1. 停止宿主后备份配置、各插件 credentials 与 src/data；备份视为秘密，目录 0700、文件 0600。
2. 在副本中运行安装及 `bash scripts/test.sh`，通过后启动新内核。
3. 旧凭证在读取时不改写；首次更新生成 `.migration.bak` 并原子写入 envelope。业务动作输出的 credentialUpdate 也遵守 generation 校验。
4. 回退代码时同时选择一致的数据备份。旧代码不能直接读取 formatVersion 2；迁移备份仅代表迁移前时刻，不能保证旧 Token 在轮换后仍有效。需要保留最新凭证时，先在副本中将当前 envelope 的 secret 与 account 元数据导出为旧布局，并核对旧插件是否支持该凭证结构。
5. unknown 动作保留幂等记录，由操作者核对上游实际结果；不能通过删历史来自动重试。
